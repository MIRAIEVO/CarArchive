# 车影归档 · CarArchive 第二版

Windows 本机汽车照片整理工具：导入 → 调整分组 → 识别与修改 → 确认归档。只使用你的 Gemini API Key，不要求其他接口或 Key。

## 开始使用

1. 运行发布目录中的 CarArchive.exe，保留整个目录，不要只复制 EXE。升级前关闭旧版程序。
2. 顶部「…」→「设置与 API 检查」保存 Gemini API Key；可使用两张合成测试图检查模型与联网能力。检查会实际请求 Gemini，可能计费，不会发送你的照片。
3. 选择归档根目录。默认目录为「品牌 / 英文车型名」，不自动重命名已有目录。
4. 「导入一组」选择同一辆车的一张或多张照片；「批量导入」选择拍摄文件夹（仅顶层）。拖入照片时也可选择方式。
5. 无须确认分组。当前组可以直接联网识别，点击某张缩略图即设为该组代表图。
6. 看图、修改字段或文件夹名，核对固定在右下角的归档目录，点击「确认并移动」。移动前仍会展示完整目标路径，请确认后执行。

支持 JPG、PNG、WebP、HEIC/HEIF。HEIC/HEIF 依赖本机 Windows 解码器；失败时显示扩展提示，原图保持不变。RAW、视频和云端相册不属于本版范围。

## 快速导入与操作布局

导入先登记文件，不等待全部缩略图。后台优先使用系统缓存或内嵌缩略图，只在点击时生成高清预览，并预取同组相邻照片。重复引用共享缓存；并发解码限制为两个任务，避免占满电脑资源。

后台读取拍摄时间后，只调整尚未被你操作的分组。有 EXIF 时间的照片按时间排列，缺失时间的照片按文件名自然排序，并保守地单张分组。你已经选择或编辑的分组不会在后台重排。

- 左栏：分组列表；Ctrl / Shift 多选后可合并。
- 可多选分组并用顶部「删除选中分组」移除分组记录；源照片文件、已归档目录和其他组均不会更改。有未完成文件操作的分组需先恢复或撤销。
- 左栏底部「删除所有已归档分组」可一次清理全部已归档分组记录；已归档项目会淡化并划线显示，不再显示绿色完成点。
- 中间：尽量大的预览；拆分、复制组、排除/恢复、框选、清除框选和查看原图均直接可见。
- 右栏：上部字段与来源可滚动，下部文件夹名称、品牌目录、已有车型目录和确认归档固定。
- 窄窗口：使用顶部「分组 / 照片 / 复核」工作区切换。
- 修改字段后可手动生成名称；识别成功后会自动生成，并可点击「撤回名称」恢复上一次名称。
- 「查看原图」调用系统图片查看器，可进一步放大。

## 文件夹名称自动补全

在右下角「车型文件夹名称」输入车型、代号或品牌关键词，会显示已有分类建议。建议合并当前归档根目录下的车型文件夹与本机记住的名称，忽略大小写及多余空格；可输入多个关键词，例如 `a4 b9`。每项列出名称、品牌和完整目标路径，最多显示 20 项。

用鼠标点击，或用方向键选择后按 Enter，会同时填入名称和品牌目录；Esc 关闭建议。选中只修改当前组的归档目标，不改变识别字段，也不移动照片。没有匹配时可继续自由命名。标注「尚无目录」的记忆名称会在确认归档时才创建目录。更改名称或根目录后，目标路径随当前输入重新计算。

## 分组并行与状态点

默认允许两个 Gemini 任务同时执行；归档使用一个独立文件队列，可与查询并行。当前正在查询、排队或归档的组暂停修改，其他分组照常浏览、编辑、识别和归档。

- 红点：任务正在执行。
- 绿点：任务完成，识别结果仍需你复核。
- 黄色：失败或取消，悬停可查看原因。
- 灰点及「排队」文字：等待执行或尚无任务。

「取消本组」仅取消该组。任务完成只更新所属组，不覆盖你正在编辑的另一组；后台归档也不会把你从其他组跳走。应用重启后，未完成的查询标记为中断，不自动重发付费请求。中断的文件操作需在操作记录中恢复。

## 复制分组：同一张照片中的两辆车

选中未归档、未执行任务的组，点击「复制分组」。新组位于原组后面，复用照片与显示缓存，但清空车型、名称和框选。两组可分别框选不同车辆、识别及命名。

每个目标目录保存完整原始照片，不会把你的分析裁剪当作原图归档：

- 第一组归档后，若仍有其他待归档组使用这张照片，源文件会保留。
- 最后一组成功归档、校验后才删除源文件。
- 仅排除或放弃其他引用，不会因这次编辑而自动删除源文件。
- 撤销一个组只撤销该组副本，其他组的副本保留。
- 原位置已有相同且已核实的共享原图时可复用；内容不同则停止，绝不覆盖。

## 识别档位与 Token

本版升级后默认「精简字段」，其他档位仍可切换：

| 档位 | 图片与行为 |
| --- | --- |
| 精简字段 | 代表图/框选一张，长边最多 1280，仅返回九个英文车型字段；一次请求，不自动追加核验 |
| 准确优先 | 最多八个视角，有歧义且额度允许时追加一次核验 |
| 速度优先 | 最多三张照片，一次联网识别 |
| 控制费用 | 一张代表图起步，可手动深入查证 |

精简字段包括品牌、车系、具体型号、车身形式、官方完整营销名称、代次、代号、改款、套件。车身形式仅在官方来源确认的完整营销名称中明确出现时填写，否则留空；官方完整营销名称会在复核面板中显示；目录名由本机生成。对支持的 Gemini 3/4 模型设置低思考档，总生成预算为 4096 tokens；该预算包含思考，截断会提示人工重试，不自动追加费用。

「联网来源与用量」展示供应商返回的输入、输出、思考用量、实际搜索次数及检索方式。缺失指标显示未知，不将输出长度直接当作完整账单。每批请求上限包含识别、核验、视觉分组、能力检查和失败请求；设置中可重置批次。

实际节省比例取决于模型、图片与内部搜索，不承诺固定费用或百分比。

## 检索设置与能力边界

设置页提供：

- 自动：仅在所选模型已通过图片资料检索检查时使用该能力，否则使用普通 Google 搜索。
- 普通 Google 搜索：沿用当前模型的联网能力。
- Gemini 图片资料检索：只有通过专门能力检查才启用；不会自动换成图像生成模型。
- Google Lens 以图搜图：界面标明当前 Gemini 接口不能提供，不伪装成已支持能力。

图片资料检索是根据图像提出候选、检索资料，不等于把照片提交到 Google Lens 反向搜索。开启联网工具也不保证服务端只执行一条搜索；程序显示实际返回的搜索记录。无搜索、无可核实来源或结果冲突时显示「未完成查证」。

无法从照片看出的发动机或配置不会因搜索到车型资料就被确认。具体版本证据不足时应退回车系。用户始终可以人工纠正后确认归档。

## 命名学习

三种互斥模式保留：

- 记住车型、通用规则另行确认（默认）：确认归档时记住精确名称，推广品牌用词前展示建议。
- 自动学习：保存精确名称，并自动推广明确的车身/改款用词替换。
- 仅手动学习：只有点击「记住名称」才影响以后。

规则列表可编辑、停用、删除和导出；已确认车型名也可编辑或删除。品牌目录别名同样可记住。规则仅影响命名，不作为识别车辆的证据，不训练模型。

任意格式修改优先记为该车型完整名称；不擅自推广代号、排量或配置。新一次识别会自动按最新字段及学习规则生成名称，旧名称可撤回。

## 数据、归档与升级

- 原图不重编码；分析图片单独重编码且不复制原始 EXIF/GPS。
- 原图位置变化时，历史浏览仍可显示已有缓存；重新识别和归档仍需要有效原图。
- 归档使用临时副本 → SHA-256 校验 → 发布目标 → 再次核对 → 按共享引用情况删除源文件。跨盘同样适用。
- 同名不同内容追加序号；同名相同内容时提示人工排除或换目录，不自动删除重复图。
- 「操作记录与恢复」可查看每张图的源、目标、阶段和错误。文件占用、内容变化或目标冲突时保留文件并停止。
- 有中断文件操作的组，需先恢复或撤销，才能继续拆分、合并或复制。
- SQLite、缓存及日志位于 %LOCALAPPDATA%\CarArchive。API Key 使用 Windows DPAPI 当前用户加密保存，不写入数据库或规则导出。
- 首次升级自动创建一致的 cararchive.pre-v2-*.db 备份，再迁移为按组及原图增量保存；已有规则、目录与 Key 保留。
- 手动备份请先关闭程序，再复制数据目录。不要用旧版本同时操作已经升级的工作区。

快捷键：Ctrl+Enter 确认归档；Alt+← / → 切换分组；Ctrl+Z 撤销最近归档。

## 构建与验证

需要 .NET 10 SDK、Windows App SDK / WinUI C# 工具链及 Windows SDK。

构建：dotnet build .\CarArchive.csproj -p:Platform=x64

核心测试：dotnet run --project ..\CarArchive.Tests\CarArchive.Tests.csproj

发布：.\Build.ps1

发布为 x64 自包含应用，位于 artifacts\win-x64。Debug 版本的 --verify <目录> 必须配合隔离的 CARARCHIVE_DATA_DIR；验证生成 500 张 12MP 合成照片，并使用明确标记的假识别器验证乱序结果、独立编辑与并行文件操作，不消耗用户 API Key。

验证不能代替真实车辆准确度和实际 Gemini 总 Token 测量。联网接口依据 Google 官方 [图像理解](https://ai.google.dev/gemini-api/docs/image-understanding)、[搜索](https://ai.google.dev/gemini-api/docs/google-search)、[思考预算](https://ai.google.dev/gemini-api/docs/thinking)及 [Interactions API](https://ai.google.dev/gemini-api/docs/interactions)。模型能力变化时请使用设置页检查。
